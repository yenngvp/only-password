# F004-base32

Added `onlypassword_core::base32`: `encode` (upper case, unpadded), `decode`
(tolerant, trailing bits not checked), `decode_strict` (also rejects non-zero
unused trailing bits), `parse_totp_secret` (10..=128 bytes -> `SecretVec`),
`normalize_totp_secret` (-> `SecretString`), `hex_encode` / `hex_decode`
(lower case only, even length). Errors are `Error::InvalidInput`. No new dependency.

Decisions the spec left open:
- Trailing `=` is accepted in any count (the acceptance example `gezd gnbv-gy3t=`
  has a "wrong" count); `=` anywhere before a symbol is rejected. Symbol counts
  of 1, 3, 6 mod 8 are rejected.
- `parse_totp_secret`/`normalize_totp_secret` are tolerant about non-zero trailing
  bits; normalize re-encodes the decoded bytes, so output always has zero trailing bits.
  Use `decode_strict` for the SK (`OPSK1-`, 52 chars) and for `Item::validate`
  canonical-form checks (compare `normalize` output to the stored text).
- The vector test parses `spec/vectors/base32.json` by hand (serde_json is not a
  dependency yet; the criterion says none may be added).
